# Initial programme and logo preparation

TV Guide ships the prepared main-channel SVG logos and complete logo index. The 37 large archive bundles are no longer installed under the custom component directory. Their manifest fixes the exact commit in **criticallimit/HA-TV-Guide**, archive size and SHA-256. The application never accesses an installed add-on or its repository for downloading.

The backend downloads the missing packages automatically after startup, using its owned worker pool alongside programme refreshes. Files are streamed with bounded size and timeout, verified, then atomically installed under the config entry's `.storage/tv_guide_store/<entry>/logos/<revision>` directory. HTTPS redirects are rejected. No credentials or tokens are needed. Completed packages survive an interrupted download, HA restart and integration update. The entry's existing removal hook removes its logo cache when the integration is deleted.

The source URL currently points to immutable archive objects in the integration's existing Git history. Removing the archives from the current source tree therefore shrinks both the installation package and future GitHub main source downloads, while the pinned historical objects remain available. A later library version requires an updated, verified manifest and index; there is no unverified remote manifest or automatic moving-branch update.

Downloads stop cooperatively on unload. Network or integrity errors retain valid packages and retry on the existing five-minute maintenance cycle. An authenticated retry action resumes them immediately. Logos are served locally through the existing indexed artwork route. Missing logos receive a noncacheable 404 so the original renderer displays its text fallback; the guide redraws as verified packages arrive. All main-channel logos remain available without any download.

On the first opening of the sidebar or dashboard card during initial preparation, a translated dialog shows programme activity, source attempts and the exact number of installed logo packages. It can be closed while background work continues. A small status button reopens it; failed downloads provide Retry. Completion is persisted in the integration's own storage. There is no progress percentage or ETA for programme providers, whose total workload is unknown.

Offline tests use small original logo samples and simulated downloads to verify size, hash, restart, failed downloads, interruption, cache repair and unsafe metadata. The real HA smoke uses those same samples, never live logo or programme providers. A separate development check downloaded and verified all 37 pinned packages and all original object hashes. Browser checks retain the original country/language pixel comparisons and exercise progress, dismissal, reopening, retry and completion.
